# 第1步：PaSa与官方参考数据分析

## 1. 当前目的

在编写评测脚本和检索基线前，先确定：

1. 查询字段是什么；
2. 标准答案字段是什么；
3. 标准答案元素究竟是标题、arXiv ID、DOI还是结构化对象；
4. 查询日期如何表达；
5. PaSa论文指标与代码指标是否一致；
6. 比赛官方是否公开了可机器读取的评测集与提交格式。

## 2. 已确认的PaSa公开实现事实

PaSa由Crawler和Selector组成：

- Crawler生成检索式、调用搜索，并沿论文引用关系扩展候选；
- Selector对候选论文逐篇判断是否满足查询；
- 检索与扩展得到的论文都进入论文队列；
- 引文候选不是天然正例，仍需Selector判断。

公开运行脚本读取RealScholarQuery时使用：

```python
data["question"]
data["source_meta"]["published_time"]
data["answer"]
```

公开指标脚本对预测标题和答案标题执行极强标题归一化：

```python
letters = [c for c in title if c.isalpha()]
normalized = "".join(letters).lower()
```

然后进行集合级TP、FP、FN计算。该规则会：

- 删除空格、标点、数字和公式；
- 无法可靠区分仅数字不同的论文标题；
- 不能处理同名论文；
- 不能显式合并arXiv与正式出版版本；
- 可能产生错误匹配。

因此ScholarPath必须保留两套口径：

### PaSa复现口径

用于与PaSa论文/开源结果对齐：

- 以标准化标题匹配；
- 复现Crawler Recall、Precision、Recall、Recall@K。

### ScholarPath严格口径

用于项目内部可靠评测：

- 优先DOI；
- 其次arXiv ID；
- 再次OpenAlex/Semantic Scholar ID；
- 最后才使用标题、作者、年份的模糊匹配；
- 所有版本合并与模糊匹配必须保留审计记录。

## 3. RealScholarQuery的已知特征

公开论文说明：

- 共50条真实、细粒度学术查询；
- 查询日期统一为2024-10-01；
- 每条查询先由多种方法建立候选池，再由专业标注者判断；
- 判定原则是论文需满足查询中的全部条件；
- 除非查询明确要求，否则综述论文应排除；
- 每条查询平均约15.82篇答案论文，中位数9篇，P90为37篇。

真实文件下载后，必须用本步骤脚本重新验证这些统计，不能只抄论文数字。

## 4. 官方竞赛数据的当前边界

截至本步骤实施时，公开赛题页可以确认赛题名称及企业命题附件，但尚不能据此假定：

- 官方隐藏评测一定使用RealScholarQuery；
- 官方答案一定按标题匹配；
- 官方输出数量固定为20、50或100；
- 官方F1采用macro还是micro；
- 官方是否合并预印本与正式版本；
- 官方是否允许输出“部分相关”。

因此当前工程决策为：

1. PaSa/RealScholarQuery作为第1个内部基准；
2. 官方提供的数据包到手后，必须运行同一检查脚本；
3. 在官方字段与提交格式未确认前，不冻结最终评测接口；
4. 评测层必须支持可插拔ID解析与匹配策略。

## 5. 当前输入格式

脚本输入为UTF-8 JSONL，每行一个JSON对象。

最低支持的PaSa形式：

```json
{
  "question": "complex academic query",
  "answer": ["Paper Title A", "Paper Title B"],
  "source_meta": {
    "published_time": "20241001"
  }
}
```

## 6. 当前输出格式

脚本输出：

- `dataset_profile.json`：机器可读结构报告；
- `dataset_profile.md`：人工审阅报告。

报告包含：

- 字段覆盖率；
- 字段类型；
- 查询字段识别；
- 答案字段识别；
- 日期路径识别；
- 答案元素类型；
- 答案数量统计；
- 空查询、空答案、重复查询；
- 日期解析错误；
- 是否允许进入下一步。

## 7. 验收标准

全部满足才通过：

- JSONL读取成功率100%；
- 查询字段覆盖率100%；
- 标准答案字段覆盖率100%；
- 标准答案元素表示形式已明确；
- 查询日期可解析；
- 数据统计可复现；
- PaSa复现口径与ScholarPath严格口径已书面区分；
- 不再把PaSa的标题归一化规则误称为官方比赛规则。

## 8. 常见错误

1. 把论文中的示例arXiv ID误认为JSONL的答案字段一定存ID；
2. 直接使用PaSa的`keep_letters`作为最终实体对齐方案；
3. 将Crawler候选池Recall和最终Recall混为一谈；
4. 用候选池结果计算Precision；
5. 忽略查询日期，检索到查询日期之后的论文；
6. 将数据集中不存在的新增相关论文直接计为TP；
7. 在官方格式未确认前写死输出Top-K。
